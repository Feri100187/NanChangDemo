# Demo01 桌面浏览器试玩包

虚构旧城关卡玩法原型，使用 LayaAir 3.4.1。本包不需要 LayaAir IDE。
源提交 SHA、分支、构建时间和逐文件 SHA-256 见同目录 `BUILD.json`；`draft` 必须为 `false` 才是正式交付。

## 启动

需要已安装的 Node.js 18 或更高版本，以及支持 WebGL 的桌面浏览器。解压整个 ZIP 到普通目录，保留目录结构。
Windows 双击 `start.cmd`，保持窗口打开，在浏览器进入终端显示的 `http://127.0.0.1:8080/`。
也可在包目录运行 `node serve.cjs`；端口被占用时运行 `node serve.cjs 8081`（Windows 也可 `start.cmd 8081`）。
服务只监听本机，按 Ctrl+C 停止。不要直接双击 index.html，不需要 npm install。
缺少 Node.js 时启动器会提示并退出，不下载软件、不修改系统或防火墙。

点击“开始游戏”取得控制。WASD 移动，鼠标转向，左键开火／短刀轻击，右键瞄准／短刀重击，R 装填，空格跳跃；其他按键见开始菜单。
当前已提交主线为曲折小巷关卡：五名队友沿主路探路，七个区域各有三名敌人，共 21 名；玩家靠近当前入口才激活该波，清完后继续前往下一入口。七波清除后，在尽头任务屋的桌上找到文件，靠近并瞄准后按 F，再进入白色撤离圈。此关不使用旧松柏巷的全图增援。
2.8 米内瞄准门窗按 F 开关。关门须瞄准转开后的实际门板，原来的空门洞不会触发；窗户沿用固定开口交互。门窗遇到角色会停止移动，移开后继续。
按 C 切换蹲下／站起，按住 Q/E 左右探头。实际关卡配置以包内 BUILD.json 对应提交和开始菜单为准。
Esc 暂停，点击“继续游戏”恢复；失焦也会暂停。设置可调音量和灵敏度。同浏览器、同地址端口保留设置，游戏进度不保存。

## 最多四步人工验收

1. 启动并开始，体验移动、转向、枪械、短刀与逐发装填；确认双臂、敌人动画及声音可见／可听。
2. 依次清理七个区域，先不取文件进入白色撤离圈确认不会获胜，再回任务屋瞄准文件按 F，进入撤离圈检查胜利。
3. 游戏中 Esc 暂停，调整设置，返回并继续，检查进度保留且暂停期间不能行动／取件。
4. 重开检查五名队友、21 名尚未激活的敌人、关闭的门窗、文件、100 HP 和 5/45 弹药恢复；让敌人击败玩家，再从失败界面重开。

## 验证范围和已知问题

包内 `VALIDATION.md` 保留旧灰盒版本的历史发布检查，不能作为新提交运行通过的证明。每次交付都应重新构建并验证对应提交，记录当前关卡、控制台和资源请求结果。
场景与动作仍为现有原型；墙边死亡姿态、极端视角双臂和完整关卡体验由成员最终验收。发布工具包含武器变换矩阵刷新修复，避免 Web 加载时忽略现有缩放配置。
较窄窗口中，顶部操作说明可能超出画面；开始菜单仍提供完整操作说明。建议使用横向桌面窗口。本轮没有扩展做 HUD 重排。
用户提供模型的权利归原提供方，仓库未建立对外公开素材分发许可；素材署名见 `CREDITS.txt` 与 `audio-credits.md`。

## 构建说明

维护者使用提交对应源码和已安装的 LayaAir IDE 3.4.1；停止预览，关闭并重开 Demo01 场景，确认当前脚本属性已导入。
使用 IDE 的 Web 发布（完整构建，不是只重新编译脚本），默认输出 `release/web`。配置固定启动 Demo01、压缩脚本、关闭源码映射和 bin 附带文件复制。
先提交源码，再重新完整发布，最后执行 `node tools/package-playtest.cjs release/web <新的独立输出目录>`。
IDE 会复用 `library/minifiedJsCache` 并保留旧时间戳；若打包器报告输出早于提交，先将 `release/web` 和 `library/minifiedJsCache` 移到 `.tmp` 下的新备份目录，再完整发布。不要修改时间戳来绕过检查。
脚本检查提交状态、构建时间、启动场景及任务绑定，从真正的 Web 产物收集运行依赖，添加启动器、说明、署名和 BUILD.json。
开发中可追加 `--draft` 生成不可交付的临时测试包。不要把 release、library 或大批构建文件提交进仓库。
最后用独立静态服务测试该目录，压缩整个目录。包内不含 IDE 缓存、源 FBX／Blend、原始下载音频或离线资源生成器。
