# AI 感知、寻路与跳跃输入修复

验证日期：2026-10-03。使用项目的 LayaAir 3.4.1 和本机 IDE 预览。

| 问题 | 修复后的行为 |
| --- | --- |
| 探头后仍判定不可见 | 重建姿态后恢复当前探头量；移动、转向和探头完成后重新感知，每帧只更新一次警戒值，射击使用最终眼位的可见性。探头回收后也不能沿用旧可见结果开火。 |
| 看得见但不能射击的掩体 | 从配置的观察点、枪膛和枪口缓存站立几何，计入朝向、侧移和枪械倾斜；候选掩体必须通过头部探出限制、眼位视线、眼位到枪膛、枪膛到枪口及枪口到目标检查。 |
| 提前跳过拐点 | 接近拐点时，只有当前位置能直达下一点才跳过；不可达的缓存路径立即失效，从当前实际位置重建。距必要拐点不足 5 厘米仍会走到拐点。 |
| 地坪边缘卡住或悬空 | 路径边逐段检查支撑高度，允许 25 厘米以内的上阶和 50 厘米以内的下阶；实际移动贴地，离地角色按重力下降。迈阶查询保留原有头顶高度检查。 |
| 无目标时每帧扫描 | 死亡或失效目标立即清空；候选搜索统一服从 250 毫秒截止时间，无目标也不绕过节流。 |
| 暂停恢复时空格补跳 | 跳跃按下沿同时排除原生键盘事件的 `repeat`；释放后再次正常按下仍可起跳。 |

控制器回归运行方式：

```powershell
node tools/check-ai-input-regressions.cjs D:\a\LayaAirIDE\resources\node_modules\typescript
node D:\a\LayaAirIDE\resources\node_modules\typescript\bin\tsc --noEmit
```

原生物理脚本沿用仓库的 `async page => { ... }` 预览测试格式，运行前需要重新加载最新编译代码。脚本在独立测试区域临时摆位和创建碰撞体，结束后刷新预览，恢复场景配置。

寻路仍是单层街区网格，不包含跳跃、攀爬或跨楼层导航；大于上阶/下阶限制的边不用于行走路径。本次验证覆盖列出的回归场景，未进行整关通关和平衡验收。

## 侧后方接近误触发交战修复（2026-10-03）

原先 `canSeePlayer` 对 6 米内的目标跳过视野角度判断；同时，扫描目标仅在 Idle/Patrol 状态检查角度。听见枪声进入 Alert 后，或者已经与其他角色交战时，也会从侧后方选中从未见过的目标。

现在近距离发现同样受配置的视野角度限制；新目标在任何状态下都要通过视野检查。只有当前目标已有有效观察记忆时，才保留原有的转身追踪能力。听见枪声仍按声源位置快照搜索，不能直接获得背后角色的位置；受击警觉及墙体遮挡检查继续生效。

本次验证：

- **PASS**：TypeScript 全项目 `--noEmit` 编译及改动文件 `git diff --check`。
- **PASS**：`tools/check-ai-input-regressions.cjs` 共 13 组控制器回归。新增的背后发现检查在修复前失败，修复后通过；覆盖近距离、6 米边界、旋转朝向、视距、遮挡、双方听觉警戒、目标切换及观察记忆。
- **PASS**：`tools/check-enemy-perception-runtime.js` 共 30 项真实 Laya/Bullet 检查。覆盖 2/5.9/6/6.1/20 米的正面和后方目标、连续侧后方接近、枪声搜索、正面实际开火、战斗中不切换到未知后方角色、记忆失效、受击和完整墙体遮挡。
- **PASS**：再次运行 `tools/check-known-ai-issues-runtime.js`，原有 86 项掩体、探头、枪口与移动检查通过，敌军和队友分别触发 5 次开火事件。

感知回归在独立预览中临时摆位，固定巡逻和战斗位移以隔离视野判断；枪声检查也固定朝向。结束后刷新还原场景。未进行整关实战和平衡验收；巡逻自然转身后将玩家纳入视野仍会正常发现玩家。
