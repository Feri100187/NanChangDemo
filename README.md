# NanChangDemo

LayaAir 3.4.1 第一人称灰盒玩法原型。默认启动 `assets/Demo01.ls`；也可以在 IDE 中打开它并运行当前场景。点击“开始游戏”取得鼠标控制后进入战斗；按 Esc 暂停，点击“继续游戏”恢复。`assets/Scene.ls` 保留为原有系统测试场，仍可点击画面直接试玩。两者复用同一套玩家、枪械、EnemyAI 和 LevelController。

## Demo01 关卡

本关是虚构布局的玩法原型，不复原或宣称对应任何真实历史地点。路线为：安全出生区 → 右转小巷 → 街口交火 → 掩体折返通道 → 院落 → 简易目标建筑 → 建筑后方终点。橙色地面标线和 HUD 的简短路线提示共同指路。

街口和院落各有 2 名敌人，全部为 100 HP，沿原有 X 方向 ±1.6 米巡逻。建筑、门洞与两次折返隔墙分隔视线；出生区不会直接暴露给敌人，前后两组也不共享一条贯通射线。外圈高墙封闭路线，目标建筑两侧的封墙要求玩家通过前后门抵达终点。两处蹲射掩体高 0.9 米，配合现有 AI 瞄准角色中心的射线，使站立和下蹲的暴露程度有区别；高掩体可完全遮挡视线。主要门洞宽 4～5 米、高 3.2 米，目标建筑前后门宽 2.4 米、高 2.8 米。

| IDE 节点 / 属性 | 用途 |
| --- | --- |
| `SpawnPoint_SafeZone` | 本关出生点与朝向，初始位置 `(-10, 1.1, 4)`；开局和跌落恢复均使用此点 |
| `Demo01_Blockout` 下的 `00_Bounds_Closed`～`06_TargetBuilding` | 外圈边界、出生区建筑、转角、两处交火区、掩体和目标建筑；实体块均带静态碰撞 |
| `Street_Enemy01/02`、`Courtyard_Enemy01/02` | 两组敌人，X/Z 为 `(-4,-20)`、`(5,-23)`、`(-6,-45)`、`(6,-48)` |
| `RouteFloorMarkers`、`RouteHintPoints` | 地面引导标线与提示点；提示点的节点名就是 HUD 文案，位置决定提示切换时机 |
| `07_ExitZone` | 建筑后方终点，中心 `(0,1,-60.2)`，半尺寸 `(1.3,2,1)` 与地面标记对应 |
| 根节点的 `LevelController` | 只统计 `enemies` 数组指定的本关 4 名敌人，配置目标文案、终点、路线提示和重开场景 |

路线提示仅用于引导，不增加额外通关条件。清敌后进入终点获胜；提前站在终点内清敌，仍须离开再进入。失败或胜利后“重新开始”返回当前关卡，恢复位置、生命、敌人、弹药和提示进度。跌落只返回本关出生点并重置路线提示，不补充生命、弹药或复活敌人。若在 IDE 移动敌人，请同时为整个横向巡逻范围和身体留出墙体间距。

## Demo01 开始与暂停

打开关卡后先显示标题、虚构原型说明、任务及操作提示。点击“开始游戏”或“继续游戏”，成功取得鼠标控制后才恢复战斗；该次菜单点击不用于开火。IDE 阻止 Pointer Lock 时沿用画面内转向方式，仍须由这两个按钮主动取得控制。

战斗中按 Esc、释放鼠标锁定、离开窗口或隐藏页面都会暂停；返回窗口不会自动继续。暂停保留生命、弹药、敌人状态、换弹剩余时间、冷却及空中运动状态，清除按键、开火输入与临时声光反馈。“重新开始”复用场景重载，返回开始界面并恢复 100 HP、5/45 弹药和 4 名敌人。结算与重开主动释放鼠标不会改成暂停。

开始、暂停和结算共用根节点 `LevelController` 与 `ResultPanel`；新增 `StartContinueButton` 由 `continueButton` 引用，按钮及文字可在 IDE 编辑。没有配置此引用的 `Scene.ls` 保持直接试玩模式，不需要补齐新 UI。

`src/GameClock.ts` 是关卡持有的轻量时钟，扣除暂停时间供枪械、后坐力、伤害提示与 AI 冷却使用。3D 场景使用独立 Timer，UI 时钟继续运行；暂停通过 3.4.1 的物理更新开关冻结原生运动，不重建角色碰撞体。场景重载会释放旧时钟、输入监听和物理暂停持有者。反馈组件暂停时保持订阅，清理当前声音、闪光与方向提示，恢复后可继续使用。

## Demo01 设置

开始界面和 Esc 暂停界面均可点击“设置”。总音量范围为 0～100%，0 为静音，作为全部战斗音效的统一倍率，保留 `CombatFeedback` 中各音效的基础音量比例。装填音量和挥刀音量各有独立的 0～100% 滑块，与总音量相乘；挥刀音量同时控制轻击和重击。鼠标灵敏度范围为原默认值的 0.25～3.00 倍，默认 1.00 倍对应 0.18 度/像素。

滑块支持点击轨道及拖动握把，调整立即生效；点击“恢复默认”恢复三项音量 100% 和 1.00 倍灵敏度。关闭面板会禁用全部四个滑块的拖动，并忽略隐藏状态的变化事件。点击“返回”或按 Esc 只返回原菜单，继续战斗仍需点击“开始游戏”或“继续游戏”。设置页不解除暂停，也不会把菜单点击作为射击输入。

`src/GameSettings.ts` 使用本地存储键 `NanChangDemo.settings.v1` 保存设置，重开和同一浏览器来源下刷新均保留；旧存档缺少装填、挥刀音量时使用 100%，存储不可用时仍可在本次运行中调整。`src/SettingsController.ts` 管理界面、灵敏度应用和监听清理；设置 UI 与引用仅配置于 Demo01，Scene.ls 保持直接试玩。

验证时依次检查：开始菜单调节 → 开始游戏体验转向和枪声 → Esc 暂停再次调节 → 返回后继续 → 重开及刷新检查设置保留。另检查音量 0% 时双方枪声静音、恢复默认、滑块两端及较小预览窗口。原测试场应继续能以 100 HP、5 发弹仓和 4 名敌人启动。

## 旧城街巷美术（整关第一版）

Demo01 使用灰砖墙脚、暖灰抹灰、深色木门窗、内收瓦檐与石板铺地。出生区、转角小巷与第一处街口的美术保留在 `Scene3D/OldTownArt_SpawnToStreet`；后半段单独放在 `Scene3D/OldTownArt_TransitionToObjective`，其中 `01_CoverTransition`、`02_Courtyard`、`03_TargetBuilding_ExteriorInterior`、`04_RearBoundary`、`05_RearPaving` 分别用于编辑掩体通道、院落、目标建筑内外、后半外圈墙及铺地。本关仍是虚构玩法原型，不对应真实历史地点或建筑。

重复构件使用 `assets/resources/oldtown/prefabs/` 下的 `ClosedWindow.lh`、`ClosedDoor.lh`、`TileEave.lh` 三个预制体，分别可编辑门窗比例、构件变换和材质引用。后半段复用封闭窗和瓦檐，并增加 `OpenPortal.lh` 门套预制体，净空为 2.4×2.8 米，正面朝本地 +Z，原点在地面中央；其前后共四个实例装饰目标建筑两道真实门洞的内外两面，不带门板。窗格、瓦面、门套均合并为网格，不逐砖逐瓦生成节点。六份共享材质位于 `assets/resources/oldtown/materials/`，使用引擎标准 BlinnPhong 材质；墙面、木材、瓦和铺地的颜色及法线纹理位于 `textures/`。后半段没有复制或修改这些共享材质，也没有增加贴图。

网格与纹理均为本工程原创程序资产，生成源为 `tools/generate-oldtown-art.cjs`，沿用 MIT 许可，无第三方下载素材。运行 `node tools/generate-oldtown-art.cjs` 可重建 `models/OldtownModules.glb` 与十张 512×512 纹理；预制体引用该模型导入后的原生网格子资源，模型的 `.meta` 应一并保留以稳定 UUID。

后半段的原创补充网格为 `models/OldtownRearModules.glb`（28 个合并网格，约 614 KiB），由 `node tools/generate-oldtown-rear-art.cjs` 离线重建，不触碰第一段模型和纹理，也不在游戏运行时搭建场景。生成器读取 Demo01 原灰盒尺寸，并输出到 `.tmp/oldtown-rear-manifest.json` 供资源维护时对照；不会自动改变 IDE 中的实例位置。`OpenPortal.lh` 使用新模型的 `@lm0` 子资源，其余外观网格由场景直接引用。目标建筑以石脚木门套、对称封闭窗和较低瓦檐区别于院落围墙；内部只有原有空间的木护墙、木顶板和储物块表皮，没有新增房间或障碍。

碰撞仍由 `Demo01_Blockout` 的原节点承担。美术替换只关闭原 MeshRenderer，没有停用原节点或碰撞组件。装饰窗明确封闭并收在原墙体内，瓦檐、门套不伸入通行净空；可通行门洞仍是原有的开口。第一段组内 `03_OriginalGrayBoundaryContinuation` 的两个后半灰色墙尾现在仅关闭 MeshRenderer，由后半独立组的同尺寸外观接替；第一段其他节点与原共享资源保持不变。铺地高度 0.015 米，低于原橙色路线标线和终点标记。编辑外观时应同时对照原碰撞尺寸，避免扩大构件、覆盖洞口或挪入通道；局部变化应覆盖当前实例，不修改共享预制体影响全关。

## 共用操作与系统测试场

Demo01 的 `CombatFeedback` 组件提供基础战斗反馈：玩家与敌人每次实际开火触发一次短枪声和枪口闪光，开始装填、轻击、重击分别触发对应音效；警戒状态不触发。普通命中显示橙色 `×`，击倒显示金色 `✦` 与“敌军击倒”文字；开镜隐藏普通准星时，命中标记仍可见。命中提示继续使用 RifleController 的真实伤害结果，不另外统计击倒。Scene.ls 也配置基础战斗音效，沿用直接试玩方式。

玩家实际扣血时，屏幕边缘短暂变红，中心附近的红色三角指向受击瞬间相对于相机的攻击来源。方向提示会淡出，之后转头或敌人移动不会让它继续跟踪；没有来源位置的伤害仅显示边缘效果。反馈不会改变相机角度、移速、伤害或 AI 状态时序。

根节点 `CombatFeedback` 可调整双方音量、闪光时长、受击边缘强度和提示时长；各枪械模型下的 `PlayerMuzzleFlash` / `EnemyMuzzleFlash` 节点可调整视觉尺寸。UI 使用现有新版 UI，不拦截鼠标。Scene.ls 不需配置这些新增引用，仍可运行。

枪声文件位于 `assets/resources/combat-feedback/`，是 `tools/generate-combat-audio.cjs` 生成的原创合成占位音，沿用工程 MIT 许可，没有第三方录音素材。两段 WAV 为 22.05 kHz、16 位、单声道，长度分别为 95 / 115 毫秒，用于验证开火时机和音量，后续可替换为正式音效。运行 `node tools/generate-combat-audio.cjs` 可确定性重建。

装填、轻击、重击音效由 `tools/generate-weapon-audio.cjs` 生成，长度分别约 3.2、0.42、0.67 秒。装填声按开栓、装填、闭锁的顺序合成，配合现有 3.3 秒装填流程；挥刀声使用扫频气流噪声。取消或完成装填会停止对应声道。暂停会停止当前短音效，继续时不从头补播；下一次有效动作仍可正常播放。

播放使用本地 3.4.1 声明中的 SoundManager / SoundChannel，首次点击通过引擎已有 AudioContext 启用音频。音效先准备再播放，未就绪或失败时跳过声音，不积压补播。结算、场景停用和销毁会停止本关声道、清除闪光与提示、解绑事件，并使未完成的加载和解锁回调失效；声道本身也会被同步停止，避免旧声音在加载完成后继续播放。

系统测试场 `Scene.ls` 包含 100×100 米平地、网格参照、使用胶囊碰撞体的玩家、第一人称相机和操作提示。玩家已换为提供的人物模型，低头可见身体与腿部，头颈在第一人称运行时隐藏。
两侧有盒体拼接的简易房屋，中央通道旁有两段错开的掩体墙。门洞可以进入，实体墙与屋顶带静态碰撞，会挡住玩家、敌军视线和双方的射线射击；窗板是封闭墙面上的外观装饰。
普通移动 / 疾跑 / 蹲行速度为 5 / 9 / 2 米每秒；玩家站立高 2 米，下蹲高 1.2 米。
开镜移动速度为 1.5 米每秒，按住右键时 Shift 不会触发疾跑；松开右键后恢复原有移动速度。
在 Player 节点的 PlayerController 组件中可以调节速度、起跳速度和鼠标灵敏度。WASD 按视角水平朝向移动，仰视或俯视不会让角色飞起或钻地。
如果 IDE 内嵌预览阻止鼠标锁定，点击画面后仍可在画面范围内移动鼠标转向；按 Esc 退出该模式。

玩家和敌人的枪械均使用用户提供并指定为汉阳造的 7.92 毫米栓动步枪外观，继续使用射线命中检测，没有实体子弹。玩家初始弹仓 5 发、备弹 45 发，单次点击单发；两次射击至少间隔约 1.33 秒（游戏射速上限 45 发/分钟），HUD 显示“拉栓中”。装填耗时 3.3 秒，弹仓打空后自动装填；拉栓或装填期间的点击不排队，长按不会连发，装填后必须重新按下左键。备弹耗尽且弹仓为空时显示“弹药耗尽”。

短刀外观由 `KnifeView` 生成并在场景销毁时释放，和汉阳造共用武器挂点。射击、轻击、重击的冷却跨武器生效，冷却期间不能切换武器；切换不会重置射击计时。允许切换时，切刀会取消正在进行的装填并停止装填声，弹仓和备弹保持取消前的数值，切回枪需重新开始装填。

轻击和重击分别在约 160/310 毫秒的挥刀中段做一次准星射线判定，沿用头、躯干、腿的伤害倍率，最近的墙体或其他遮挡物会挡住攻击。长按不重复挥刀，轻重击不能叠加，重击不能取消动作后立刻接枪。卡顿若跨过整次挥刀动画则丢弃待结算命中，不追补过期伤害。暂停冻结换弹、挥刀和攻击冷却，继续后完成尚未结束的动作；重开会取消旧场景的待结算伤害，恢复持枪和 5/45 弹药。

枪上保留与射线方向一致的小红点作为瞄准参考，原橙色占位瞄具边框已隐藏。按住右键时，相机会移到与红点共线的视点，完全对齐后屏幕十字准星会隐藏；松开后返回普通视点，视野角始终是 60°。腰射每发让镜头上抬 1.35°、准星上抬 0.45°，开镜每发让镜头上抬 1.8°；另有左右交替的 0.12° 小幅水平后坐。枪身后移 0.10 米，再以 0.32 米/秒回位。射线始终沿当前准星方向发射，开镜时红点保持在画面中心；射击后后坐角度逐渐恢复，长按左键也不会卡住回正。

场景配置了 4 名独立敌军，每名初始 100 HP，复用同一套 EnemyAI。其状态为 Idle、Patrol、Alert、Combat、Dead：短暂站岗后在几个固定点间巡逻，看到玩家会逐渐警戒，进入战斗后转向并用射线开枪；玩家跑出视距或被物体挡住时，警戒下降并能重新巡逻。血量、警戒和攻击计时均由各自实例保存。敌军每次射击造成 18 点伤害，射击间隔为 1.8 秒；警戒、巡逻与攻击判定流程不变。玩家初始 100 HP，归零后立即判负。

系统测试场的 4 名敌军初始 X/Z 坐标分别为 `(0, -15)`、`(-4, -13)`、`(4, -19)`、`(0, -25)`，沿原有 X 方向 ±1.6 米的范围巡逻，避开两侧房屋和掩体墙。本轮没有加入寻路。

玩家步枪从实际命中的碰撞节点向父级查找 EnemyAI，按部位结算伤害：头部 175、躯干和手臂 70、腿部 45.5（实际扣血不超过目标剩余血量）。敌军血量归零后进入永久 Dead，外观和碰撞一起关闭，每名敌人只计数一次。HUD 显示剩余人数和最近一次命中反馈，不再固定绑定某名敌军。

系统测试场的任务是先清除这 4 名指定敌军，再进入中央通道尽头的橙色终点区（地面中心 X/Z 为 `0/-31`，地面标记为 5×5 米）。提前进入不会获胜；若在终点内击杀最后一名敌人，需要先离开再进入。终点采用位置范围判断，不增加实体阻挡。

胜利或失败后显示结算界面，停止敌军、射击、换弹和玩家控制，清除输入并释放鼠标。点击“重新开始”会先加载同一关卡，成功后销毁旧的 2D/3D 场景及其脚本，再打开新实例；玩家位置、生命、4 名敌人、弹药、任务和场景状态随之恢复。重开按钮的尾随点击不会取得鼠标控制：Demo01 需要点击“开始游戏”，Scene.ls 则再次点击画面。加载失败会保留结算界面，允许重试。

移动和碰撞使用 Bullet CharacterController。姿态切换在落地时生效，空中保持起跳时的姿态；头顶有遮挡时保持下蹲。
斜向移动会归一化，按住空格不会自动连跳，失焦会清除输入，跌落场地下方后会返回本关出生点。没有配置 `spawnPoint` 的测试场会使用玩家的初始位置。

移动控制位于 `src/PlayerController.ts`，枪械、AI、生命值分别位于对应控制器。`src/LevelController.ts` 挂在 Scene2D 根节点，通过场景引用配置指定敌人、终点、任务提示和结算界面；新增脚本的 `.meta` 与场景一起保留。节点和物理组件均保存在场景中。
针对 IDE 3.4.1 的旧组件热重载报错，项目内的 `src/EditorHotReloadGuard.ts` 仅在场景编辑器中生效。

以上射速、后坐力、装填时间和伤害均为本关的游戏化平衡值，不作为历史武器性能数据；没有新增拉栓骨骼动画或真实弹道模拟。

## 枪械模型资源

来源为用户提供的 `GUN` 文件夹，原始 FBX 和 `.fbm` 贴图目录完整保存在 `assets/resources/weapons/ProvidedGun/`。`ProvidedRifle.glb` 是坐标归一化后的运行资源，包含颜色、法线、金属度和粗糙度信息；`textures/` 是 IDE 从 GLB 提取的运行贴图，须连同 `.meta` 一起保留。没有另行下载模型或贴图。

Demo01 和 Scene.ls 各有 1 把玩家枪、4 把敌人枪，共 10 处实例，全部复用 `ProvidedRifle.lh`。在 IDE 中编辑该公共预制体可调整网格和材质引用；场景实例以反向缩放抵消原占位节点的非均匀缩放，保持枪身比例。保留原枪械控制节点、射线与开镜控制、暂停时钟和敌人受击碰撞，只隐藏旧枪身和瞄具框的 MeshRenderer。弹量、伤害、单发节奏、装填时间和后坐力参数按上述栓动步枪方案调整，数值可在 RifleController 与 EnemyAI 中编辑。枪口闪光节点已移动到新模型枪口附近。

如需从源文件重建运行模型，可用 Blender 5.2 在独立后台进程运行 `blender --background --factory-startup --python tools/prepare-provided-rifle.py`。脚本不修改源 FBX/贴图，将枪口朝向统一为本地 -Z，并对齐既有瞄准线；敌人实例旋转 180° 朝向本地 +Z。导出后由 IDE 重新导入，保留现有 `.meta` 的 UUID。

## 角色模型资源

玩家和敌人分别使用用户提供的 `player`、`enemy` 模型，原始 FBX 与 8192×8192 贴图完整保存在 `source-assets/characters/`，不直接作为发布资源。两份源模型各有 41 根骨骼，没有动画片段。`tools/prepare-provided-characters.py` 在独立 Blender 后台进程中用原骨骼摆出敌人持枪、玩家站立和下蹲姿态，再烘焙为运行网格；原始骨骼和权重仍保留在源文件中，后续可用于制作动画。当前没有新增行走、拉栓或换弹动画。

运行资源位于 `assets/resources/characters/Enemy/` 和 `Player/`，使用 2048×2048 颜色贴图。每个目录中的 GLB、公共 `.lh` 预制体、IDE 提取的 `textures/` 和全部 `.meta` 须一起保留。Demo01 与 Scene.ls 各使用一份玩家预制体和四份敌人预制体。敌人模型高 2.55 米，沿用原目标的整体高度；原有 Head、Torso、Legs、LeftArm、RightArm 节点保留为隐藏的受击区域，按新模型对齐位置与尺寸，伤害倍率、阵营碰撞过滤、AI 状态和击倒计数保持原逻辑。汉阳造模型仍共用原枪械预制体，敌人枪的位置调整到新持枪姿态。

玩家模型高 1.8 米，`ProvidedPlayer.lh` 内的 `Standing`、`Crouching` 各包含 `Body`、`Head`。PlayerController 切换姿态组，只隐藏 Head，身体跟随水平朝向，不跟随镜头俯仰和枪械后坐力。落地时用脚下射线将外观贴合地面，空中随碰撞体升降；预制体中的 0.04 米高度补偿对应当前 Bullet 胶囊的变换偏移。站立/下蹲碰撞高度仍为 2/1.2 米，镜头眼位、移动速度、起跳和开镜行为保持不变。

重建运行网格：`blender --background --factory-startup --python tools/prepare-provided-characters.py`。脚本保留源文件，在缺少运行颜色贴图时生成 2048 JPEG，并将各姿态脚底归零、正面统一为本地 +Z；导入后应保留现有 `.meta` 的 UUID。玩家场景实例旋转 180°，与第一人称相机的本地 -Z 朝向一致。

武器状态回归可执行 `node tools/check-weapon-states.cjs <LayaAirIDE/resources/node_modules/typescript>`，覆盖单发与卡顿、切换取消装填、跨武器冷却、近战命中时机、遮挡、暂停清理、音效停止和旧设置迁移。该检查替代渲染、物理和音频宿主，仍需结合 IDE 或浏览器中的场景验证。
